# 아이폰 홈 화면 설치 준비 — 0.17.0

히트를 홈 화면에서 여는 웹 앱 설정과 설치 안내를 추가했습니다. 앱스토어 배포가 완료된 것은 아닙니다. 홈의 추가 안내, PC 왼쪽 메뉴, 계정 설정에서 `#install`로 이동합니다. 안내 열람에는 로그인이 필요하지 않습니다.

## 아이폰 사용 순서

1. Safari에서 안내받은 HTTPS 접속 주소를 엽니다.
2. 공유 메뉴에서 ‘홈 화면에 추가’를 선택합니다.
3. ‘웹 앱으로 열기’가 보이면 켜고 추가합니다.
4. 홈 화면의 히트 HIT 아이콘을 눌러 실행합니다.

iOS 버전에 따라 메뉴 위치·표현이 다를 수 있습니다. [WebKit의 홈 화면 웹 앱 안내](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)를 참고했습니다. 기기에 설치 버튼을 제공하는 브라우저는 사용자가 버튼을 누른 경우에만 설치 창을 요청합니다. 버튼이 없는 브라우저에서는 Safari 수동 절차를 안내합니다. 설치 완료를 대신 단정하지 않으며 standalone 실행 여부와 설정 로드 상태를 구분합니다.

Safari와 홈 화면 앱은 로그인 상태가 다를 수 있으므로 다시 로그인해야 할 수 있습니다. [웹 앱 설치 안내](https://web.dev/learn/pwa/installation)를 참고했습니다. 푸시·백그라운드 업로드·앱스토어 등록은 별도이며 이번 단계에 포함하지 않습니다.

휴대폰에서는 이 PC의 localhost 주소를 사용할 수 없습니다. 별도 보호된 시범 접속 주소를 사용하고 외부 접속 이메일 인증은 사용자가 직접 진행합니다. 시범 주소는 PC·앱·연결 프로그램이 실행 중이어야 유지됩니다. 주소 변경 시 아이콘을 다시 추가해야 할 수 있습니다. 시범용 외부 인증이 설치 리소스 제공을 막으면 해당 기기에서 설치되지 않을 수 있으며 이는 아직 실제 아이폰에서 검증하지 않았습니다. 고정 도메인·실제 SMTP·상시 서버 운영은 후속 작업입니다.

## 아이콘과 실행 설정

`manifest.webmanifest`에 이름·언어·같은 출처 id/scope/start_url·standalone 표시·색상과 192/512px PNG 아이콘을 지정합니다. iPhone용 apple-touch-icon은 180px입니다. [Apple의 웹 앱 아이콘 문서](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html)를 참고했습니다. 상태 표시 영역과 하단 안전 여백도 반영합니다.

아이콘은 실제 제공된 `approved-ui-v1.1.jpg`의 좌측 상단 확정 로고를 코드로 추출해 비율을 유지하고 정사각형 흰 여백에 넣습니다. 새 로고를 그리거나 생성형 이미지로 대체하지 않았습니다. 합성 JPG에서 추출한 저해상도 파생본이며 벡터·고해상도 원본을 복구했다고 주장하지 않습니다. 원본 파일은 변경하지 않았습니다. 생성 PNG는 서버 메모리에서 크기별 한 번 보관하며 DB·사용자 자료를 포함하지 않습니다.

## 연결 실패 동작

`/sw.js`는 같은 출처 루트 경로의 GET 페이지 이동에만 네트워크를 먼저 요청합니다. 네트워크 요청이 실패한 경우 정적인 한국어 연결 안내 HTML(503)을 반환합니다. 서버가 반환한 4xx/5xx나 인증 이동은 그대로 처리하고 임의로 오프라인 성공 화면으로 바꾸지 않습니다. 요청이 차단되거나 접속 보호가 로그인 페이지로 이동하면 그 정상 인증 절차를 유지합니다.

CacheStorage·IndexedDB·오프라인 사진 저장·API 응답 저장은 사용하지 않습니다. 서비스 워커는 `/api/`·사진·메일·수정 요청·외부 지도·루트 외 경로를 가로채지 않습니다. 일반 브라우저의 메모리와 기존 이 탭의 텍스트 임시 저장은 별개입니다. 기존 sessionStorage의 텍스트 24시간 임시 저장 규칙을 유지하고 사진은 임시 저장하지 않습니다. 서비스 워커는 오프라인 작성이나 자동 재전송을 수행하지 않습니다.

기기가 오프라인 상태라고 알리면 현재 앱 위에 연결 안내를 표시합니다. 온라인 이벤트만으로 서버 접속 성공이라고 주장하지 않습니다. 읽고 있던 화면을 자동으로 새로고침하지 않습니다. 처음 앱을 한 번도 열지 않았거나 서비스 워커가 지원·등록되지 않은 환경에서는 브라우저 기본 연결 오류가 나타날 수 있습니다. 설치 설정 로드만으로 오프라인 안내 준비 완료를 단정하지 않습니다.

서비스 워커 업데이트는 기본 대기 생명주기를 따르고 skipWaiting으로 작성 화면을 강제 교체하지 않습니다. 등록할 때 updateViaCache:none을 사용합니다. 연결 실패 HTML에는 스크립트·외부 자료가 없고 no-store와 제한된 CSP를 지정합니다. 스타일 허용은 이 정적 안내 응답에 한정하며 앱 본문의 CSP는 기존대로 유지합니다. [서비스 워커 탐색 요청 처리](https://web.dev/articles/handling-navigation-requests)를 참고했습니다.

## 검증

자동 검사 44개 통과. 실제 네트워크 응답·인증 이동·서버 오류 유지, 연결 실패 시 안내 HTML, API·사진·외부 지도·쓰기 요청 비개입, 매니페스트 범위와 PNG 실제 크기, 공개 설치 리소스 응답·보안 헤더를 확인했습니다. 기존 회귀 검사도 통과했습니다.

로컬 브라우저에서 설치 설정 로드·원본 로고 아이콘 표시, 서버 중지 후 새로고침 시 연결 안내, 서버 재시작 후 홈 열기와 기존 로그인 유지, 모바일 320·390px 가로 넘침 없음을 확인했습니다. 로컬 접속 점검에는 매니페스트·설치 모듈·서비스 워커를 포함했습니다. 실제 아이폰 홈 화면 추가·별도 창 실행·외부 인증과의 호환은 미확인입니다. DB 구조는 바꾸지 않았고 기존 데이터·계정은 변경하지 않았습니다.
