# 로그인 만료 후 이어쓰기 — 0.31.0

로그인이 풀린 상태에서 보호된 작업을 저장하면 서버의 401 응답을 구분해 ‘다시 로그인하고 이어가기’를 제공합니다. 오류가 났다고 자동으로 화면을 이동하거나 저장 요청을 다시 보내지 않습니다. 로그인 화면의 잘못된 비밀번호 오류나 일반 403 권한·인증 제한 오류를 세션 만료로 바꾸지 않습니다.

## 글 작성 흐름

1. 오류 화면에서 입력과 사진을 확인합니다. 그 상태에서 사진·글은 남아 있습니다.
2. 다시 로그인하고 이어가기를 누르면 기존 이탈 안내를 확인합니다. 이동을 취소하면 입력과 사진을 유지합니다.
3. 이동하면 텍스트는 기존 같은 탭·계정별 임시 저장 기능을 따릅니다. 사진과 사진 순서는 임시 저장되지 않아 다시 선택해야 합니다. 저장소 제한·브라우저 종료·만료 시 텍스트 복구도 보장하지 않습니다.
4. 같은 계정으로 로그인하면 원래 작성 화면으로 돌아갑니다. 이어쓰기로 텍스트를 복원하고 사진을 다시 고른 뒤 명시적으로 등록합니다.

복귀 주소는 기존 최대 30분·내부 경로 허용 목록을 사용하며 계정별 임시 글을 다른 계정으로 옮기지 않습니다. 게시물 수정 등은 다시 서버의 소유자 검사를 거칩니다. 프로필·신고 등 텍스트 임시 저장을 제공하지 않는 양식은 저장하지 않은 입력이 자동 복원된다고 안내하지 않습니다. 댓글 작성·편집 내용도 로그인 화면으로 이동하면 다시 확인해야 합니다.

## 검증

기본 검사 64개·별도 Chrome 화면 검사 17개·로컬 연결 점검과 보호된 시범 진단 7개가 통과했습니다. 임시 브라우저 계정의 실제 세션을 로그아웃 요청으로 종료하되 작성 화면을 유지하여 저장 거부·입력/사진 보존·이동 취소·다시 로그인·계정별 이어쓰기·사진 재선택·최종 등록을 확인했습니다. 잘못된 로그인 비밀번호에 복구 링크를 중복 표시하지 않는지와 320/390px 가로 넘침도 검사했습니다. 실제 개발·휴대폰 계정이나 글을 수정하지 않았습니다.

## 시범 연결 복구

기존 로컬·시범 서버가 종료되고 이전 임시 호스트가 해석되지 않는 상태를 확인하여 개발 서버와 이메일 한 명으로 보호된 새 임시 연결을 실행했습니다. 별도 시범 DB는 그대로 사용했습니다. 실제 이메일·임시 주소·인증번호는 저장소에 기록하지 않습니다. 주소가 바뀌면 해당 주소의 접속 인증과 앱 로그인이 다시 필요할 수 있고 브라우저 로그인·임시 글은 다른 origin으로 공유되지 않습니다. DB에 저장한 게시물은 별개입니다. 사용자의 이전 아이폰 오류가 해결됐다는 실기기 확인은 아직 받지 못했습니다.
