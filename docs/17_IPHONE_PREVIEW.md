# 아이폰용 보호된 시범 접속

별도 데이터베이스 `data/phone-preview.sqlite`와 루프백 포트 3002를 사용합니다. 기존 개발 DB는 복사하지 않습니다. 허용 이메일은 실행할 때 전달하며 이메일·인증번호·실제 시범 주소를 저장소에 기록하지 않습니다.

이 실행기는 **이메일 인증으로 보호된 Cloudflare Quick Tunnel 전용**입니다. 일반 공개 터널로 연결하지 않습니다. 외부 인증은 Cloudflare가 처리하며 이 실행기는 Cloudflare 인증 토큰을 직접 검증하지 않으므로, 인증 없는 터널에 연결하면 보호되지 않습니다. 시작 명령의 `--allowed-mail`을 생략하지 않습니다. 서버는 127.0.0.1에만 연결됩니다.

## 실행 순서

1. `cloudflared tunnel --no-autoupdate --url http://127.0.0.1:3002 --allowed-mail 본인이메일`로 보호된 터널을 시작합니다.
2. 출력에 `protected quick Tunnel`, `One-Time PIN`, 허용 수신자 1명이 표시되는지 확인합니다.
3. 발급된 주소를 설정해 시범 앱을 실행합니다.

```sh
PREVIEW_ORIGIN=https://발급주소.trycloudflare.com node server/phone-preview.mjs
```

터널은 실행 중이어도 앱은 별도로 실행해야 합니다. 시범 앱은 지정된 주소의 Host와 변경 요청의 Origin을 검사하고, 내부 앱에는 루프백 주소로 변환합니다. 인증 링크는 아이폰에서 열 수 있는 외부 주소로 변환합니다. 로그인 쿠키는 Secure·HttpOnly를 유지합니다.

## 아이폰 Safari 순서

1. 전달받은 HTTPS 주소를 Safari에서 엽니다.
2. 허용된 이메일을 입력하고 `Send login code`를 누릅니다.
3. 해당 메일로 온 인증번호를 **Safari 화면에 직접** 입력합니다.
4. 히트 화면에서 회원가입합니다. 기존 PC 개발 계정과 별개입니다.
5. 앱 설정의 `개발용 메일함`에서 앱 자체의 이메일 인증 링크를 누릅니다. 앱의 SMTP 발송은 아직 연결하지 않았습니다.
6. [휴대폰 점검표](16_PHONE_TRIAL.md)에 따라 글·사진·이어쓰기를 확인합니다.

외부 접속 인증 메일과 앱 자체 인증은 서로 다른 단계입니다. Cloudflare 접속 인증은 실제 메일을 받지만, 앱 자체 인증은 개발용 메일함을 사용합니다. 인증번호와 비밀번호를 채팅으로 보내지 않습니다.

PC가 잠들거나 앱·터널이 중단되면 접속할 수 없습니다. 터널을 재시작하면 주소가 바뀌며 새 주소로 시범 앱도 다시 실행해야 합니다. 사용이 끝나면 두 프로세스를 중지합니다. 정식 서비스 배포가 아닙니다.

## 확인 기록

- 자동 검사 25개 통과: 다른 Host·Origin 거절, 기존 DB 사용 거절, Secure 쿠키, 비로그인 메일함 거절, 외부 주소의 인증 링크, 인증 전 글 작성 거절 포함.
- 실제 터널 생성: 허용 이메일 1명·일회용 번호 인증 설정 확인.
- 미인증 외부 요청은 앱 대신 Cloudflare 인증 화면으로 이동함을 확인.
- 내부 시범 앱 상태 확인 API 정상 응답.
- 실제 아이폰 인증번호 수신·입력과 기기 조작은 사용자 확인 대기.

참고: [Cloudflare Quick Tunnels 공식 문서](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).
