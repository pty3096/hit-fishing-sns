# 커뮤니티 게시판 — 0.13.0

상단 커뮤니티 메뉴·PC 왼쪽 메뉴·모바일 홈 바로가기에서 낚시 질문과 정보를 나누는 게시판을 엽니다. 로그인·이메일 인증 후 글쓰기·수정·댓글·좋아요·저장을 이용하며, 비로그인 사용자는 공개 글을 읽을 수 있습니다.

## 글쓰기와 목록

제목 1~60자와 본문 1~2000자를 입력합니다. 사진은 선택 사항으로 최대 5장·장당 10MB인 JPG·PNG·WebP를 사용할 수 있습니다. 사진 없이도 등록하고 수정할 수 있으며 수정 시 사진을 모두 제거할 수 있습니다. 조황에는 기존대로 사진·어종·지역·방식·출조일이 필요합니다.

커뮤니티의 전체 이야기·내 글, 프로필의 커뮤니티 탭으로 글을 찾습니다. 프로필의 사진 목록과 상단 조황 수는 조황만 보여줍니다. 기존 숏폼 준비 탭은 커뮤니티 글 연결로 바꿨고 숏폼은 공통 메뉴에서 준비 상태로 남깁니다. 커뮤니티 글은 일반 조황 피드·검색·지역 카드·팔로잉 조황에 섞지 않습니다. 목록은 글 ID 역순, 20개씩 추가 조회합니다.

게시물 종류는 작성 후 바꿀 수 없습니다. 커뮤니티에 어종·출조일을 가짜로 넣지 않고 비워 저장합니다. 화면에는 출조일 대신 글 등록일을 표시합니다. 글 분류·제목 검색·대댓글·첨부 파일·비밀글·개인 메시지는 이번 범위에 포함하지 않습니다.

## 기존 기능 연결

- 작성자만 수정·삭제하고 댓글·좋아요·신고·차단은 기존 권한 검사를 사용합니다.
- 저장 목록에 조황과 커뮤니티 글을 모두 담을 수 있어 메뉴 이름을 저장한 글로 바꿨습니다. 본인만 열람합니다.
- 댓글·좋아요 알림은 커뮤니티 글에도 생성되며 기존 재시도 보호로 중복 생성하지 않습니다.
- 글 작성 요청 재시도 보호, 기존 사진 검증·위치 정보 제거도 적용합니다.
- 임시 글은 조황 신규 작성과 커뮤니티 신규 작성을 별도 키로 보관합니다. 글만 임시 저장하고 사진은 복원하지 않습니다.
- 숨김·차단·이용 제한된 글은 목록·상세·사진·저장·알림에서도 기존 공개 범위를 따릅니다. 탈퇴·원글 삭제 시 관련 자료도 기존 삭제 절차로 정리합니다.

## 데이터와 API

기존 `posts`에 `kind`를 추가했습니다. 이전 글은 자동으로 `catch`이며 신규 커뮤니티 글은 `community`입니다. 스키마 버전은 10입니다.

- `POST /api/posts`: `kind: community`, 제목·본문·선택 사진으로 커뮤니티 글 작성
- `GET /api/posts?kind=community`: 공개 커뮤니티 글, `author`와 `before` 지원
- `GET /api/posts`: 기본 조황 목록
- `GET /api/posts?saved=1`: 본인이 저장한 두 종류의 글
- 상세·수정·삭제·댓글·좋아요·신고 API는 기존 경로를 사용

운영자 신고 화면은 기존 게시물 유형으로 검토할 수 있습니다. 새로운 크리에이터 기능을 추가하지 않았습니다.

## 검증

자동 검사 34개 통과. 텍스트만 작성·종류별 목록 분리·다른 계정 수정 거절·종류 변경 거절·사진 추가 및 전체 제거·저장·알림·신고·숨김·차단·서버 재시작 후 보존·20개 페이지 경계·삭제·재시도·임시 글 분리를 확인했습니다.

로컬 브라우저에서 개발 검증용 글 1개를 사진 없이 등록·수정하고 목록에서 확인했습니다. 기존 조황 피드가 3개로 유지되고 새 글이 섞이지 않는 것, 프로필 커뮤니티 탭으로 연결되는 것, 모바일 320·390px 가로 넘침 없음을 확인했습니다. 실제 아이폰 조작은 확인 대기입니다.

로컬·시범 DB 모두 적용 전에 별도 이름으로 백업하고 무결성을 확인했습니다. 이전 조황 3개·개발 계정 2개를 보존했고, 검증 글은 로컬 개발 계정에만 추가했습니다. 시범 DB에는 테스트 글을 넣지 않았습니다. 개인 자료·백업 파일은 GitHub에 올리지 않습니다.
