# 브라우저 화면 검사 — 0.19.1

이전 낚시인 찾기 단계에서 앱 업데이트로 중단된 화면 점검을 완료하고 반복 가능한 화면 회귀 검사를 추가했습니다. 앱의 일반 사용 화면에 테스트 기능을 노출하지 않으며 새 사용자 기능이나 크리에이터 전용 기능을 추가한 단계는 아닙니다.

## 확인한 흐름

별도 Chrome 브라우저에서 실제 로컬 개발 앱을 비로그인으로 열었습니다. 닉네임 ‘검증’으로 기존 공개 검증 프로필 2개를 찾고, 프로필 열기 → 팔로우 선택 시 로그인 안내 → 뒤로 가기 후 검색 조건 유지 흐름을 확인했습니다. 320·390px 너비에서 가로 넘침이 없고 프로필 사진과 버튼이 표시되는 것을 확인했습니다. 이 과정에서 실제 계정·소개·팔로우 관계를 바꾸지 않았습니다.

프로젝트에 `tests/browser/people.test.mjs`를 추가해 다음 3개 흐름을 자동화했습니다.

1. 빈 검색 안내, 닉네임 검색, 소개의 HTML 문자열을 문자로 표시, 프로필 이동·뒤로 가기, 결과 없음, 검색 초기화, 공백 검색 오류.
2. 비로그인 팔로우 선택 시 로그인 안내, 로그인 후 원래 프로필 복귀, 팔로우 변경, 검색 결과에 팔로잉 상태·본인 프로필 구분 반영.
3. 홈에서 검색 진입, 320·390px 검색 결과의 가로 넘침 없음, 검색 버튼 높이 44px 이상, 페이지 스크립트 오류 없음.

검사 2의 로그인·팔로우 변경은 아래의 테스트 전용 DB에서만 수행합니다. 실제 SMTP·가입 인증 메일 전달 여부를 검증한 것은 아닙니다.

## 실행 방법

Node.js 24 개발 환경에서 `npm ci` 후 Google Chrome이 설치되어 있다면 `npm run test:browser`를 실행합니다. 별도 로컬 앱을 켤 필요가 없습니다. 검사 스크립트가 임의의 빈 로컬 포트에 테스트 서버를 실행합니다.

Chrome이 없는 환경은 `npx playwright-core install --with-deps chromium`으로 테스트용 브라우저와 필요한 시스템 패키지를 준비한 다음 `HIT_BROWSER_CHANNEL=chromium npm run test:browser`로 실행합니다. 로컬 Chrome 설치를 바꾸거나 기존 브라우저 프로필을 연결하지 않습니다. 공식 설치 방식은 [Playwright 브라우저 문서](https://playwright.dev/docs/browsers)를 참고했습니다.

`HIT_UI_SCREENSHOTS=/private/tmp/hit-ui-fixtures npm run test:browser`처럼 출력 경로를 지정하면 모바일 결과 이미지를 저장합니다. 기본 실행은 이미지를 저장하지 않습니다. 이미지 생성은 [Playwright 스크린샷 기능](https://playwright.dev/docs/screenshots)을 사용합니다.

## 테스트 자료 격리

매 실행마다 시스템 임시 폴더에 별도 SQLite DB를 만들고 127.0.0.1의 임시 포트에 서버를 실행합니다. 화면 검증임을 명시한 닉네임·소개, example.test 이메일과 테스트 전용 비밀번호만 사용합니다. 테스트용 인증 상태를 DB에 지정하며 외부 메일을 발송하지 않습니다. 각 테스트는 별도 브라우저 컨텍스트를 사용합니다.

개발용 `data/hit.sqlite`, 휴대폰용 `data/phone-preview.sqlite`, 실제 사용자 브라우저 세션에 접근하지 않습니다. 정상 종료 시 테스트 브라우저·서버를 닫고 임시 DB 폴더를 제거합니다. 테스트 프로그램이 실제 사용자 계정 생성·삭제·팔로우 변경을 수행하지 않습니다.

`playwright-core`는 고정 버전 1.65.1의 개발 전용 의존성입니다. 운영 이미지의 `npm ci --omit=dev`에는 포함되지 않습니다. 기존 `npm test`는 49개 서버·로직 검사를 그대로 실행하고, 브라우저 검사는 별도 `npm run test:browser`로 분리했습니다.

## GitHub 검사

GitHub에서 기존 49개 검사 후 테스트용 Chromium을 준비하고 위 화면 검사 3개를 실행합니다. 그 다음 기존 운영 이미지 빌드·HTTPS 프록시 설정 검증·메일 발송 없는 운영 실행 점검을 유지합니다. 화면 검사는 실제 운영 도메인이나 사용자의 로컬 DB로 연결하지 않습니다.

## 결과와 한계

로컬에서 기존 자동 검사 49개, Chrome 화면 검사 3개가 통과했습니다. 별도 로컬 앱의 실제 검증 프로필을 읽는 추가 화면 점검도 통과했습니다. 기능·DB 스키마는 기존 11을 유지하며 확인 중 개발 계정과 글을 변경하지 않았습니다.

모바일 너비 검사와 실제 아이폰 Safari의 설치·사진 선택·키보드·터치 검증은 다릅니다. 이번 단계는 Chrome 렌더링 검사이며 실제 아이폰 Safari와 보호된 외부 시범 접속 재인증은 아직 별도 확인이 필요합니다.

## 후속 0.20.0 검사 확장

서버·로직 검사는 51개, 화면 검사는 5개로 확장했습니다. 기존 화면 검사 파일에 조황·커뮤니티 검색용 글을 테스트 DB에만 추가하고, 제목/본문 검색·작성자 범위·전체 작성자 전환·어종/지역/방식/날짜 조합·초기화·뒤로 가기·모바일 배치를 검증합니다. 검색 클릭 뒤 API 응답과 화면 로딩 완료를 기다려 이전 목록을 검사하지 않도록 합니다. 가격 조건은 장터에만 허용하는 검사를 유지합니다.

## 후속 0.21.0 내 글 관리 검사

서버·로직 검사 53개, 화면 검사 6개로 확장했습니다. 내 글 관리 진입 시 로그인 요구와 원래 조건 복귀, 종류별 본인 글만 표시, 탭 전환 시 검색어 유지, 기존 수정 화면에서 저장 후 관리 목록 복귀, 빈 결과와 초기화, 320·390px 가로 넘침 없음을 확인합니다. 장터 글도 임시 DB에만 추가합니다. 수정 저장은 테스트 전용 커뮤니티 글에만 수행하며 실제 개발·시범 자료를 변경하지 않습니다. 선택적 화면 저장 시 로그인 알림이 사라진 뒤 관리 화면을 캡처합니다.

## 후속 0.22.0 댓글 수정 검사

서버·로직 검사 54개, 화면 검사 7개로 확장했습니다. 임시 DB의 타인 조황에 테스트 계정이 작성한 댓글을 사용해 수정 취소·네트워크 실패 후 입력 유지·재시도·HTML 문자 표시·새 댓글 작성 내용 유지·이동 취소·저장 중 이동 후 새 조황 입력 보존·비로그인 수정 버튼 미노출·320/390px 배치를 확인합니다. 실패는 브라우저의 해당 요청만 차단해 재현하고 실제 개발·휴대폰 DB는 수정하지 않습니다. 선택적 이미지는 임시 검증용 댓글 편집 화면입니다.

## 후속 0.23.0 공유 링크 검사

서버·로직 검사 55개, 화면 검사 8개로 확장했습니다. 공개 글·검색 URL의 필터 보존과 비공개 경로/토큰 제거, 아직 검색하지 않은 입력을 제외하는 동작, 복사된 URL 재접속, 복사 허용/거절 응답, 읽기 전용 직접 복사와 닫기, 320·390px 배치를 확인합니다. 브라우저 테스트는 클립보드 쓰기를 대체 객체로 바꿔 사용자 OS 클립보드 내용을 덮어쓰거나 읽지 않습니다. 이 검사는 실제 기기의 복사·붙여넣기 성공을 대신 확인한 것은 아닙니다.

## 후속 0.24.0 가입·인증·재설정 검사

서버·로직 검사 57개, Chrome 화면 검사 11개가 통과했습니다. 추가한 가입 계정은 DB의 인증 상태를 직접 바꾸지 않고 실제 UI에서 개발용 메일함의 일회용 안내를 사용합니다. 가입 후 새로고침·인증·원래 커뮤니티 글쓰기·첫 등록을 확인했습니다. 비밀번호 재설정의 확인란 불일치, 기존 세션과 이전 비밀번호 거부, 새 비밀번호 로그인 후 원래 조황 쓰기 복귀도 확인했습니다. 인증 직후 계정 조회 한 번을 실패시켜 사용한 토큰 주소 제거와 설정의 이어서 진행을 검증했습니다.

모든 변경은 임시 DB에서 수행했습니다. 선택적 이미지 onboarding-first-post.png는 가입흐름 화면검증 계정의 커뮤니티 글쓰기이며 실제 사용자 글이 아닙니다. 실제 메일 발송이나 아이폰 Safari 검증은 수행하지 않았습니다. 로컬 앱은 새 auth-return.mjs 제공과 연결 점검을 통과했습니다.

## 후속 0.25.0 모바일 인증 입력 검사

서버·로직 검사 57개·화면 검사 12개와 로컬 연결 점검이 통과했습니다. 추가 검사는 320·390px의 로그인·가입·비밀번호 찾기·인증·재설정 화면에 가로 넘침이 없는지 확인합니다. 인증 입력의 글자 크기와 표시 버튼 높이, 개별 입력란의 표시/숨김·aria-pressed·Space 조작·값 보존·의도하지 않은 제출 방지를 확인합니다. 재설정 확인란 불일치 오류도 작은 화면에서 검사합니다. 테스트 전용 값만 사용하며 실제 아이폰 Safari 확인을 대신하지 않습니다.

## 후속 0.26.0 프로필 사진 복구 검사

자동 검사 57개·화면 검사 13개가 통과했습니다. 별도 시험 계정에서 정상 이미지 선택 취소·잘못된 HEIC 재선택 후 이전 대기 파일 제거·저장 요청 실패 후 선택 유지·재시도 저장·기존 사진으로 취소 복원·320/390px 배치를 확인했습니다. 업로드 실패는 테스트 브라우저의 PUT 요청 한 번만 차단하며 실제 개발·휴대폰 사진을 바꾸지 않습니다. 실제 아이폰 Safari의 사진 보관함·선택 취소 UI는 확인하지 않았습니다.

## 후속 0.27.0 글 전송 보호 검사

자동 검사 57개·화면 검사 14개·로컬 연결 점검이 통과했습니다. 임시 커뮤니티 글과 PNG 사진을 전송하면서 요청을 잠시 보류해 입력·사진 삭제 잠금, 이동 취소, 전송 직전 텍스트의 임시 저장을 확인합니다. 첫 요청 실패 후 편집과 사진이 유지되고 같은 본문·사진·요청 식별자로 재시도되어 글 상세에 사진이 표시되는지 확인합니다. 이 검사는 실제 개발·시범 DB를 변경하지 않습니다.

## 후속 0.28.0 대표 사진·순서 검사

기본 검사 57개·Chrome 화면 검사 15개·로컬 연결 점검이 통과했습니다. 임시 빨강/파랑 PNG를 이용해 새 파일 순서 교환과 전송 본문 순서, 저장된 첫 이미지의 실제 색을 확인했습니다. 다시 편집해 기존 사진 ID 순서를 바꾸고 저장·새로고침 후 실제 이미지 순서가 유지되는지 검사했습니다. 첫/마지막 이동 제한과 320/390px 가로 넘침도 확인했습니다. 이 결과는 실제 아이폰 사진 보관함이나 Safari의 터치 검증을 대신하지 않습니다.
