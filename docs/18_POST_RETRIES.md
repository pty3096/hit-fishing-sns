# 연결 오류 후 조황 등록 재시도 — 0.8.0

등록을 눌렀는데 서버 응답이 끊긴 경우, 작성 화면에서 같은 글과 사진으로 다시 등록하면 이미 저장된 조황을 돌려줍니다. 같은 요청을 동시에 처리해도 게시물은 하나만 만듭니다. 사진 처리와 조황·요청 기록은 한 번에 저장하거나 함께 취소합니다.

클라이언트는 전송 내용의 SHA-256 지문과 무작위 요청 번호를 사용합니다. 같은 작성 화면에서 같은 내용을 재전송할 때 번호를 재사용하고, 내용이 바뀌면 새 번호를 만듭니다. 서버는 계정별 요청 번호와 내용 지문·게시물 연결을 SQLite에 보관합니다. 원본 사진을 요청 기록에 중복 저장하지 않습니다. 서버 재시작 후에도 같은 번호로 재요청하면 기존 결과를 확인할 수 있습니다.

같은 번호로 다른 내용을 보내거나, 이미 등록한 글이 삭제·숨김된 상태에서 재시도하면 새 글을 만들지 않고 오류를 안내합니다. 로그인·인증·이용 제한 검사는 재시도에도 적용합니다. 탈퇴 시 요청 기록도 삭제합니다. 글 삭제 시 요청 번호는 남기고 게시물 연결만 비워 삭제된 글이 재생성되지 않도록 합니다. 스키마 버전은 6입니다.

## 범위

- 신규 조황 등록에 적용합니다. 기존 요청 번호 없는 API 호출은 이전 방식과 호환됩니다.
- 화면 이탈·새로고침 후에는 전송 번호를 복원하지 않습니다. 이 경우 내 조황 목록에서 등록 여부를 먼저 확인해주세요.
- 임시 저장은 글만 보관하며 사진과 요청 번호는 보관하지 않습니다.
- 댓글·신고·회원가입 등의 중복 전송 방지는 이번 변경 범위에 포함하지 않습니다.

## 확인

자동 검사 27개 통과. 서버 재시작 후 같은 요청 재전송, 내용 충돌, 잘못된 요청 번호, 다른 계정의 동일 번호, 동시 전송, 삭제된 글 재전송, 비로그인 요청을 검증했습니다. 실제 아이폰에서 네트워크 전환 중 응답이 끊기는 상황은 아직 확인하지 않았습니다.

기존 로컬·시범 DB는 적용 전에 백업·무결성 검사를 완료했습니다. 계정·게시물·사진·백업 파일은 GitHub에 올리지 않습니다.
