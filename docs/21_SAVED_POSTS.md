# 개인 저장 목록 — 0.10.0

관심 있는 조황의 `저장` 버튼을 누르면 본인 저장 목록에 담깁니다. `저장됨`을 다시 누르면 해제됩니다. 내 프로필의 저장 탭 또는 PC 왼쪽 저장한 조황 메뉴에서 확인할 수 있습니다. 본인 게시물도 저장할 수 있습니다.

## 공개 범위

저장 목록은 로그인·이메일 인증을 마친 본인 계정에만 제공됩니다. 저장한 사람 목록이나 전체 저장 수는 공개하지 않으며 다른 사용자 프로필에 저장 탭도 표시하지 않습니다. API의 계정 번호를 임의로 지정해도 현재 로그인 계정의 저장 목록만 조회합니다. 이용 제한된 계정은 사용할 수 없습니다.

원글이 숨김·이용 제한·차단으로 보이지 않으면 저장 목록에서도 제외하고 상세·사진 접근을 기존 권한 범위대로 제한합니다. 숨김·차단을 해제하면 원글을 다시 볼 수 있는 경우 기존 저장 항목이 나타납니다. 원글 삭제 시 저장 연결을 삭제하고, 회원 탈퇴 시 해당 회원의 저장 목록도 삭제합니다. 이미 보이지 않는 원글은 목록과 저장 변경 API에서 접근할 수 없습니다.

## 저장 방식

`PUT /api/posts/:id/save`, `DELETE /api/posts/:id/save`는 같은 요청을 반복해도 중복 행을 만들지 않습니다. `GET /api/posts?saved=1`은 본인에게 보이는 저장 조황만 기존 조황 ID 역순으로 최대 20개씩 반환합니다. 저장한 시간순 정렬은 이번 범위에 포함하지 않습니다. 저장 항목은 SQLite에 보관해 서버 재시작 후에도 유지합니다. 스키마 버전 8에 `saved_posts`를 추가했습니다.

다른 사람의 공개 조황 응답에는 현재 방문자가 저장했는지만 포함되며 타인의 저장 여부는 포함하지 않습니다. 외부 사용자에게 저장 알림·메일을 발송하지 않습니다.

## 검증

자동 검사 29개 통과. 두 계정의 저장 목록 분리·임의 계정 번호 무시, 비로그인 접근 거절, 반복 저장·해제, 페이지 경계, 서버 재시작 후 유지, 숨김·차단 적용, 원글 삭제·탈퇴 시 연결 삭제를 확인했습니다.

PC 브라우저에서 조황 상세 저장 → 내 목록 → 새로고침 후 유지 → 해제 후 빈 목록 안내를 확인했습니다. 모바일 크기에서도 목록과 프로필 저장 탭을 확인했습니다. 기존 로컬·시범 DB를 각각 백업하고 무결성 검사 후 적용했습니다. 실제 아이폰 조작은 별도 확인이 필요합니다.

이전 사용자 요청으로 삭제한 크리에이터 전용 메뉴·기능은 추가하지 않았습니다.
