# 가입·인증 후 작업 복귀 — 0.24.0

로그인이 필요한 글쓰기·프로필·내 글 관리 등의 화면을 열면, 로그인 또는 가입·이메일 인증 후 원래 작업으로 돌아갑니다. 새로고침해도 같은 탭의 복귀 목적지를 유지합니다. 인증은 권한을 우회하지 않으며 이용 제한 계정은 설정에서 상태를 확인합니다.

## 사용 흐름

1. 비로그인 상태에서 글쓰기 등 원하는 작업을 엽니다.
2. 로그인하거나 회원가입하고 이메일 인증 안내를 확인합니다.
3. 같은 탭에서 인증을 완료하면 원래 화면으로 돌아갑니다. 글 등록은 내용을 입력하고 등록 버튼을 눌러야 합니다.
4. 인증은 성공했지만 계정 상태를 다시 불러오지 못하면 사용한 인증 주소를 제거합니다. 설정 화면에서 상태를 다시 읽은 뒤 ‘이어서 진행하기’로 복귀할 수 있습니다. 계속 연결이 안 되면 연결을 확인하고 다시 시도해주세요.

비밀번호를 잊었다면 로그인 화면의 비밀번호 찾기를 이용합니다. 재설정 후에는 모든 기존 로그인이 종료되며 새 비밀번호로 로그인해야 합니다. 이 탭에 남은 복귀 목적지가 유효하면 로그인 후 이어서 진행합니다.

## 저장 범위

복귀 목적지는 sessionStorage에 최대 30분 보관합니다. 허용한 내부 화면만 저장하며 내 글 관리의 종류·검색어 외 매개변수는 제거합니다. 비밀번호·이메일·인증/재설정 토큰은 저장하지 않습니다. 복귀 시 한 번 소비하며 로그아웃·탈퇴 때도 삭제합니다. 저장소를 쓸 수 없으면 현재 실행 중 메모리만 사용하므로 새로고침 복귀는 보장되지 않습니다.

다른 기기나 새 탭에서 연 안내는 원래 탭의 복귀 정보를 공유한다고 보장하지 않습니다. 만료·손상·지원하지 않는 목적지는 내 프로필로 돌아갑니다. 로그인·인증·재설정 경로 또는 외부 주소를 복귀 목적지로 허용하지 않습니다. 본문 임시 저장은 기존 별도 기능이며 이 기능은 작성 내용이나 사진을 저장하지 않습니다.

## 검증과 한계

임시 DB와 별도 Chrome에서 실제 가입 → 개발용 메일함 → 일회용 인증 → 새로고침 → 첫 커뮤니티 글 등록을 확인합니다. 재설정 확인란 불일치, 이전 비밀번호 거부, 기존 세션 종료, 새 비밀번호 로그인 후 조황 쓰기 복귀도 검사합니다. 인증 직후 계정 조회 실패는 해당 브라우저 요청 한 번만 차단해 재현합니다.

개발용 메일함의 안내를 사용하며 외부 SMTP로 메일을 보내지 않습니다. 실제 개발·휴대폰 DB와 사용자 브라우저 세션은 변경하지 않습니다. 스키마 11을 유지합니다. 실제 아이폰 Safari, 외부 메일 수신, 공개 배포는 이번 확인 범위에 포함되지 않습니다.

자동 검사 57개·Chrome 화면 검사 11개 및 로컬 연결 점검이 통과했습니다.
