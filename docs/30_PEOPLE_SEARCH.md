# 낚시인 닉네임 검색 — 0.19.0

홈의 ‘함께할 낚시인 찾기’, 커뮤니티의 찾기 링크, PC 왼쪽 ‘낚시인 찾기’에서 `#people` 화면으로 이동합니다. 이전 요청으로 삭제한 크리에이터 전용 기능을 복구한 것이 아니라 기존 일반 사용자 프로필과 팔로우의 검색 진입점을 추가한 것입니다. 확정 시안의 로고·색상을 재사용하며 검색 화면 배치는 이번 구현입니다.

## 사용 범위

검색어는 앞뒤 공백을 제외한 닉네임 1~30자입니다. 닉네임의 일부가 포함된 사용자를 찾으며 이메일·소개 글은 검색 대상이 아닙니다. 빈 검색은 전체 사용자 명단을 열거하지 않고 검색 안내와 빈 결과를 제공합니다.

결과에는 공개 닉네임·소개·프로필 사진과 현재 방문자의 팔로잉 여부를 표시합니다. 본인에게는 ‘내 프로필 보기’를 안내하고, 다른 사용자는 프로필을 열어 기존 조황·커뮤니티·장터 글과 팔로우 기능으로 이동합니다. 팔로우는 기존 로그인·이메일 인증·이용 제한 검사를 그대로 적용합니다. 검색 화면에서 바로 팔로우 관계를 변경하지 않습니다.

로그인하지 않아도 공개 검색을 열람할 수 있습니다. 로그인한 경우 현재 계정과 어느 방향으로든 차단 관계인 사용자를 제외합니다. 이용 제한된 사용자는 검색에서 제외하며 본인이라도 검색에 나타나지 않습니다. 일반 프로필의 본인 조회 규칙과는 구분합니다. 닉네임 변경·탈퇴 후 다음 검색 요청에 변경을 반영합니다. 비로그인 방문자에게는 특정 계정의 차단 목록을 적용할 수 없습니다.

계정 ID 역순으로 최대 20명씩 표시하고 다음 결과를 추가 조회합니다. 이것은 인기·활동·추천 순위가 아니며 전체 검색 결과 수를 표시하지 않습니다. 검색어를 주소에 보관해 새로고침·프로필 방문 후 뒤로 가기에 사용할 수 있습니다. 자동 오타 수정·추천 계정·지역 기반 추천·크리에이터 등급은 제공하지 않습니다.

## API·공개 정보

`GET /api/users?q=닉네임&before=계정ID`를 제공합니다. `before`는 선택 사항인 양의 안전 정수입니다. 결과는 `users`와 `next`이며 각 사용자 항목의 허용 필드는 `id`, `nickname`, `bio`, `avatar_url`, `followed`뿐입니다. 이메일·비밀번호·인증 상태·운영 권한·이용 제한 플래그·세션은 반환하지 않습니다. `followed`는 방문자의 관계만 나타내며 비로그인은 false입니다.

SQL 매개변수와 LIKE 문자 이스케이프를 사용해 `%`, `_`, 역슬래시도 문자 그대로 검색합니다. SQL OR 구문을 입력해도 권한·검색 범위를 우회하지 않습니다. 프로필 사진 주소는 기존 공개 범위 검사를 그대로 적용합니다. 검색 화면의 닉네임·소개 등은 HTML 이스케이프를 적용합니다.

새 DB 테이블이나 사용자 자료를 만들지 않으며 스키마는 11입니다. 검색을 위해 외부 서비스·위치 권한·추가 개인정보·오프라인 데이터 저장을 도입하지 않았습니다. 개발·휴대폰 시범 계정과 글은 변경하지 않았습니다.

## 검증과 남은 확인

자동 검사 총 49개 통과. 부분 검색·문자 이스케이프·공백 정리·비공개 이메일/소개 검색 제외·반환 필드 허용 목록·빈 검색·길이/페이지 커서 검증·아바타 연결·계정별 팔로잉 여부·양방향 차단·이용 제한·닉네임 변경·탈퇴·20명 페이지 경계를 확인했습니다. 테스트 전용 계정과 자료는 임시 DB에 생성하며 실제 개발 DB에는 추가하지 않았습니다.

작업 중 Codex 앱 업데이트로 실행이 중단되어 로컬 앱과 별도 시범 앱을 다시 실행했습니다. 복구 후 로컬 접속 점검이 통과했고 실제 서버에서 기존 개발 검증 프로필 2개의 닉네임 검색, 공개 필드 5개만 반환, 빈 검색에서 전체 계정을 반환하지 않는 것을 확인했습니다.

업데이트 후 기존 화면 자동화 도구가 제공되지 않아 이번 검색 화면의 실제 클릭·프로필 이동·반응형 배치와 실제 아이폰 조작을 확인하지 못했습니다. 화면 표시나 모바일 가로 넘침 검사를 완료했다고 주장하지 않습니다. GitHub 반영·자동 검사와 실제 기기 검증은 구분합니다. 설치·외부 시범 주소의 재접속 상태도 별도 확인이 필요합니다.
