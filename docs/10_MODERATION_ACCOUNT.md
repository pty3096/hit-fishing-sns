# 신고·차단·운영·탈퇴

## 사용 흐름

- 게시물 상세의 게시물 신고, 댓글의 댓글 신고, 사용자 프로필의 사용자 신고에서 사유를 입력합니다.
- 사용자 프로필에서 차단 내용을 확인하고 차단합니다. 내 프로필 → 설정에서 목록을 보고 해제합니다.
- 운영자 계정은 내 프로필 → 설정 → 운영자 신고 관리에서 미처리·처리 완료 목록과 신고 상세를 엽니다.
- 설정의 회원 탈퇴에서 현재 비밀번호와 확인 문구 `탈퇴`를 입력해 삭제합니다.

## 차단

로그인한 두 계정 사이에 차단 관계가 있으면 양쪽의 게시물·사진·댓글이 숨겨지고 좋아요·댓글·팔로우가 제한됩니다. 직접 API 주소에도 적용합니다. 차단 시 양방향 팔로우를 해제하며, 차단을 풀어도 팔로우는 자동 복구하지 않습니다. 다른 사용자 목록에서는 차단 관계의 계정을 제외합니다.

이는 로그인 계정 기준의 차단입니다. 로그아웃 상태에서는 공개 조황을 볼 수 있습니다. 전체 좋아요·팔로우 수는 집계값이며 차단으로 과거 좋아요를 삭제하지 않습니다.

## 신고와 운영 조치

신고 사유는 1~300자입니다. 자기 콘텐츠 신고와 동일 대상의 중복 미처리 신고를 막고, 계정당 한 시간에 최대 20건을 접수합니다. 신고만으로 콘텐츠를 자동 숨기지는 않습니다.

운영자는 사유를 기록하고 다음 조치를 적용합니다.

- 신고 종결: 콘텐츠를 변경하지 않고 처리 완료로 표시
- 게시물·댓글 숨김 또는 복원
- 작성자 이용 제한 또는 제한 해제

제한 계정의 콘텐츠는 공개 조회에서 숨기고 기존 세션을 폐기합니다. 다시 로그인하면 제한 상태를 안내하고 작성·소통을 차단합니다. 제한 상태에서도 자기 계정 탈퇴는 가능합니다. 처리 완료된 신고에서도 복원·제한 해제를 추가 기록할 수 있습니다. 삭제된 대상은 종결만 가능합니다.

신고 상세와 조치 이력은 운영자만 볼 수 있습니다. 숨긴 사진도 별도의 운영자 전용 주소로 검토할 수 있으며 일반 사용자에게는 공개하지 않습니다. 계정 이메일·비밀번호 해시·세션은 신고 검토 화면에 반환하지 않습니다.

## 운영자 계정 지정

일반 회원가입·프로필 수정 API로 운영자 권한을 얻을 수 없습니다. 기본 운영자 계정이나 공통 비밀번호는 없습니다. 앱에서 사용할 계정을 먼저 만든 다음, 이 PC의 프로젝트 터미널에서 해당 이메일을 지정합니다.

```sh
npm run admin -- grant you@example.com
```

`you@example.com`은 실제 등록한 본인 계정 이메일로 바꿉니다. 운영자 권한 회수는 다음과 같습니다.

```sh
npm run admin -- revoke you@example.com
```

권한 회수는 기존 세션의 운영 API에도 즉시 적용됩니다. 검증 계정에 부여했던 임시 권한은 검증 후 회수했습니다. 현재 실사용 운영자 계정은 지정하지 않았습니다.

## 회원 탈퇴와 자료 범위

비밀번호와 확인 문구가 맞아야 삭제합니다. 활성 데이터베이스에서 계정·작성 조황·사진·댓글·좋아요·팔로우·차단 관계·전체 세션을 삭제하고 쿠키를 만료시킵니다. 다시 로그인할 수 없으며 삭제한 자료를 앱에서 복구할 수 없습니다.

접수된 신고와 운영 이력은 남습니다. 탈퇴한 신고자의 계정 연결과 해당 신고 사유는 제거·대체하고, 운영 조치자의 계정 연결은 비웁니다. 타인이 쓴 신고 사유나 운영 조치 메모까지 자동으로 모두 삭제하는 방식은 아닙니다. 개발 중 만들어둔 백업 파일도 자동 수정하지 않습니다. 공개 서비스 이전에 운영 기록과 백업의 보존·파기 기준을 확정해야 합니다.

계정과 게시물 번호는 별도의 증가 카운터로 배정해 삭제 후 다른 사람이나 게시물에 재사용하지 않습니다. 오래된 신고가 새 대상을 가리키지 않게 하기 위한 처리입니다.

## API와 저장 구조

스키마 3: 사용자에 운영자·제한 상태, 글과 댓글에 숨김 상태, `blocks`, `reports`, `moderation_actions`, `id_counters`를 추가했습니다. 기존 계정·게시물·사진은 유지하며 업그레이드 전 백업했습니다.

| 요청 | 기능 |
| --- | --- |
| POST /api/reports | 신고 접수 |
| GET /api/blocks | 내 차단 목록·페이지 분할 |
| PUT, DELETE /api/blocks/:id | 차단·해제 |
| DELETE /api/account | 비밀번호와 확인 문구로 본인 탈퇴 |
| GET /api/admin/reports | 상태별 신고 목록·페이지 분할 |
| GET /api/admin/reports/:id | 대상 내용·조치 이력 |
| POST /api/admin/reports/:id/resolve | 종결·숨김·복원·제한·해제 |
| GET /api/admin/photos/:id | 운영자 전용 사진 검토 |

## 확인 결과와 남은 작업

자동 검사 8개에서 기존 계정·사진·소통 기능과 함께 차단 우회 방지, 운영 권한 거부, 숨김·복원, 제한·해제, 탈퇴 인증·연관 자료 삭제·번호 재사용 방지를 확인했습니다.

브라우저에서 검증 신고 접수, 차단·해제, 운영자 신고 검토·숨김·복원·이력 표시를 확인했습니다. 실사용 계정 탈퇴는 수행하지 않았습니다.

[이메일 인증·재설정](11_EMAIL_AUTH.md)은 개발용 메일함과 SMTP 연결 설정까지 구현했고 [프로필 사진](13_PROFILE_PHOTO.md)도 연결했습니다. 실제 SMTP 서비스·실사용 운영자 지정과 공개 배포는 후속 작업입니다. 현재 로컬 개발 앱입니다.
