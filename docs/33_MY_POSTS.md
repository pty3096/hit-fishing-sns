# 내 글 관리 — 0.21.0

내 프로필의 내 글 관리, PC 왼쪽 메뉴, 계정 설정에서 `#my-posts`로 이동합니다. 로그인·이메일 인증을 완료한 정상 계정이 현재 볼 수 있는 본인의 글을 찾아 수정하는 화면입니다. 기존 확정 로고·색상과 수정 기능을 재사용합니다.

## 사용 방법

- 조황·커뮤니티·장터 중 하나를 선택합니다. 기본은 조황입니다.
- 제목·본문에 포함된 검색어로 현재 종류의 내 글을 찾습니다. 80자 이내이며 빈 값은 해당 종류의 내 글 전체입니다.
- 종류를 바꿔도 검색어를 유지합니다. 검색어 지우기는 종류를 유지하고 검색어만 초기화합니다.
- 대표 사진·제목·본문 일부·기존 날짜 정보를 봅니다. 장터 글에는 가격·판매 상태도 표시합니다.
- 수정하기는 기존 작성자 전용 수정 화면으로 연결합니다. 글 보기는 상세로 이동하며 삭제는 기존 상세 화면의 확인 절차를 사용합니다. 관리 목록에서 일괄 삭제하지 않습니다.
- 종류에 맞는 새 글쓰기와 빈 목록 안내를 제공합니다. 목록은 기존 글 ID 역순 20개씩 추가 조회합니다.

검색 조건은 주소에 보관합니다. 상세·수정 화면에서 브라우저 뒤로 가기로 돌아오면 종류·검색어를 다시 적용합니다. 기존 상세/수정 화면의 고정 피드·게시판 링크는 해당 공개 목록으로 연결되므로 관리 목록으로 돌아가려면 브라우저 뒤로 가기 또는 내 글 관리 메뉴를 이용합니다.

## 권한과 표시 범위

기존 `GET /api/posts?mine=1&kind=catch|community|market&q=검색어`를 재사용합니다. 화면은 현재 로그인 계정 기준의 mine=1을 고정해서 전달하고 URL의 다른 계정 번호를 작성자로 사용하지 않습니다. 서버에서도 로그인한 본인 조건을 적용합니다. 임의의 author를 함께 지정해도 다른 계정의 글을 대신 조회하지 않습니다.

숨김 처리된 글·이용 제한 상태 등 기존 공개 범위에서 볼 수 없는 자료는 관리 목록에도 표시하지 않습니다. 관리 화면으로 숨김 글을 복원하거나 수정 권한을 우회할 수 없습니다. 권한·요청 출처·사진 처리·임시 저장·등록 재시도 보호는 기존 수정 화면의 규칙을 유지합니다.

새 API나 DB 구조를 추가하지 않았고 스키마는 11입니다. 기존 계정·게시물·사진·가격·알림 자료를 변경하거나 이동하지 않았습니다. 크리에이터 전용 메뉴·관리 권한은 추가하지 않았습니다.

## 검증

자동 검사 53개 통과. 종류별 두 계정 자료 분리, 비로그인 거절, 본인 조건과 다른 작성자 조건 조합 시 타인 자료 미노출, 숨김 글 제외, 검색 조건과 20개 페이지 경계, 관리 링크의 mine=1 고정과 URL 보존을 확인했습니다.

Chrome 화면 검사 6개 통과. 로그인 요구와 원래 관리 조건 복귀, 본인의 조황·커뮤니티·장터만 표시, 탭 전환 시 검색어 유지, 수정 화면 진입·커뮤니티 제목 수정 저장·뒤로 가기 후 변경 반영, 결과 없음·검색어 초기화, 320·390px 가로 넘침 없음을 확인했습니다. 수정 작업은 임시 테스트 DB의 검증용 글에만 수행했습니다. 실제 개발 계정·글·사진은 변경하지 않았습니다.

선택적 화면 저장 결과는 테스트용 계정과 글을 사용하는 검증 화면입니다. 실제 아이폰 Safari의 키보드·터치 조작은 별도 확인이 필요합니다.
