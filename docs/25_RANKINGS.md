# 인기 조황 랭킹 — 0.14.0

홈의 랭킹 바로가기 또는 PC 왼쪽 랭킹 메뉴에서 인기 조황을 봅니다. 비로그인 사용자도 공개된 조황의 순위를 열람할 수 있습니다. 크리에이터·사람 순위는 만들지 않습니다.

## 집계 기준

- 최근 7일, 최근 30일, 전체 기간 중 하나를 선택합니다.
- 기간은 글 등록 시각에 적용하며 조회 시점에서 7×24시간 또는 30×24시간을 거슬러 계산합니다. 기간 경계를 포함하고 미래 등록 시각은 제외합니다.
- 좋아요 수는 각 글에 현재 남아 있는 누적 좋아요 수입니다. 기존 좋아요 테이블의 계정별 중복 방지 규칙을 사용합니다. 자기 좋아요나 기존 저장된 좋아요에 별도 가중치를 주지 않습니다.
- 좋아요가 1개 이상인 조황을 좋아요 수 내림차순으로 최대 20개 표시합니다. 동률은 나중에 등록한 글(ID가 큰 글)을 먼저 표시합니다.
- 커뮤니티 글·숨김 조황·이용 제한된 작성자의 조황·현재 방문자와 차단 관계인 작성자의 조황은 제외합니다.
- 각 글의 좋아요 수와 조회 시점을 함께 안내합니다. 수치를 임의로 추가하거나 가짜 예시 순위를 넣지 않습니다.

조회할 때 집계한 순위이며 새로고침하면 갱신됩니다. 목록에서 좋아요를 누르면 버튼 수치는 바뀌지만 집계 순서·상단 집계 수치는 다음 새로고침에 반영됩니다. 실시간 스트리밍·상금·보상·공인 평가 기능은 포함하지 않습니다.

글 상세로 이동한 뒤 뒤로 가기와 새로고침을 해도 선택 기간은 URL에 남습니다. 등록 글이나 좋아요가 없으면 해당 기간의 빈 순위 안내를 표시합니다.

## API·데이터

`GET /api/rankings?period=7`, `period=30`, `period=all`을 제공합니다. 기본 기간은 7일입니다. 다른 기간 값은 오류로 처리합니다. 응답에는 선택 기간·조회 시각·집계 좋아요 수가 포함된 조황 목록을 반환하며 기존 사진·좋아요·저장·댓글 상세 데이터를 재사용합니다.

데이터베이스 구조는 바꾸지 않고 기존 등록 시각과 좋아요를 읽습니다. 기존 계정·글·저장·알림 데이터는 변경하지 않았습니다. 순위 화면에서 상세·댓글·좋아요·저장으로 연결됩니다.

## 검증

자동 검사 35개 통과. 실제 좋아요 수·기간별 목록·동률 ID 순서·7일 경계 포함과 직전 제외·미래 글·커뮤니티·좋아요 없는 글 제외, 잘못된 기간 거절, 좋아요 취소 반영, 최대 20개 상한, 숨김·차단·이용 제한 처리를 확인했습니다.

로컬 브라우저에서 저장된 실제 검증 조황이 1위로 표시되는 것, 7일→30일 전환, 상세 열기 후 뒤로 가기의 기간 유지, 새로고침의 조회 시점 갱신을 확인했습니다. 모바일 320·390px 가로 넘침 없음도 확인했습니다. 실제 아이폰 조작은 별도 확인이 필요합니다.
