# 낚시 방식·출조 기간 검색 — 0.12.0

조황 찾아보기에서 어종·지역을 입력하고, `낚시 방식·출조 기간`을 펼쳐 추가 조건을 설정합니다. 어종·지역·낚시 방식·출조 시작일·출조 종료일을 함께 입력하면 모든 조건에 맞는 공개 조황을 찾습니다. 조건은 모두 선택 사항입니다.

- 낚시 방식은 일부 이름으로 검색합니다. 예: `루어`, `원투`.
- 출조 시작일과 종료일을 모두 포함합니다. 같은 날짜를 입력하면 그날의 출조 기록을 찾습니다.
- 한쪽 날짜만 입력하면 해당 날짜 이후 또는 이전 출조 기록을 찾습니다.
- 출조일 기준이며 게시물을 등록한 날짜 기준이 아닙니다.
- 시작일이 종료일보다 늦거나 실제 달력에 없는 날짜는 검색하지 않고 안내합니다.
- 전체 보기는 모든 검색 조건을 초기화합니다.

입력한 조건은 URL에 포함되어 게시물 열기 후 뒤로 가기, 새로고침 시 유지됩니다. 추가 조건이 있는 주소를 열면 입력 영역도 자동으로 펼칩니다. 빈 결과는 조건 변경·초기화를 안내합니다. 잘못된 날짜가 포함된 주소로 접속한 경우 검색 조건 초기화 링크로 돌아올 수 있습니다.

## API와 공개 범위

`GET /api/posts`의 기존 `fish`, `region`에 `method`, `date_from`, `date_to`를 추가했습니다. 날짜는 `YYYY-MM-DD`이며 실제 달력 날짜와 기간 순서를 서버에서도 검사합니다. 문자열 검색의 `%`, `_`, 역슬래시는 패턴이 아니라 입력한 문자로 처리합니다.

기존 조황 ID 역순 정렬·20개 페이지 분할을 유지합니다. 다음 페이지도 모든 검색 조건을 유지합니다. 숨김·차단·이용 제한에 따른 공개 범위는 그대로 적용됩니다. 새 표나 DB 변경 없이 기존 출조일·낚시 방식 필드를 사용합니다. 검색할 조황을 임의로 추가하지 않았습니다.

## 검증

자동 검사 32개 통과. 복합 필터, 날짜 양끝 포함, 한쪽 날짜, 윤년·잘못된 날짜·역순 범위, 특수 문자, 페이지 경계와 차단된 조황 제외를 검사했습니다. 검색 주소 생성·복원과 화면 날짜 검증도 확인했습니다.

브라우저에서는 `강릉 / 루어 / 2026-11-17~2026-11-17`로 기존 검증 조황 2개를 조회하고 상세 열기·뒤로 가기 후 조건 유지를 확인했습니다. 역순 날짜 입력 후 오류 표시·입력 유지, 올바른 날짜로 재시도, 모바일 320·390px 가로 넘침 없음도 확인했습니다. 실제 아이폰의 달력 선택 조작은 사용자 확인이 필요합니다.
